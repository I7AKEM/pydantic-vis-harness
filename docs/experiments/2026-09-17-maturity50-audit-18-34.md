## Audit method

The source and current data-agent handoff determine meaning. Historical `original_question` and corpus `coverage.chosen_chart` are provenance, not new task instructions or oracle labels. Source cells, row identities, explicit missingness, and supplied units must survive. The audit inspected every retained first/repair PNG, delivered spec, saved source, reviewer finding, and final response. Automated gate results remain unchanged and are reported separately from this agent's visual/semantic judgment. This is not human adjudication and does not certify unseen pixels.

In the JSON sidecar, `final_delivery` means the **final response embeds or links the PNG**. It does not mean the artifact was never persisted, and it is false by definition for both no-PNG boundary cases. `task_correct` separately judges semantic presentation and truthful delivery claims: complete faithful Markdown tables may satisfy the task despite a missing PNG link (27 and 28). `source_roles_faithful` includes supported meanings/units, not merely unchanged source bytes. Visual verdicts concern the inspected images, not the truth of unspecified code meanings. `chart_suitable` concerns the final chosen representation, including successful fallback; first-render loss is recorded separately. No UI interaction or external model call was performed by this auditor.

Normal cropping of a functioning scroll viewport is not itself a failure when complete content is accessible. A scrollbar painted into a PNG does not establish interactivity. Static image coverage, glyph loss, complete persisted data, and accessible delivered content will be evaluated separately.

### Case 23: partial-evidence boundary

The frozen `build_prompt` reconstructed from the saved report/design and frozen brief supplies the reviewer the first **30 of 51 rows**, with `rows_are_partial=true`. Its final supplied row is Jeddah / Vietnam / 712. Tunisia / 708 is **source row 31**, immediately outside that preview, but visibly present in the correct full PNG. Albania and Chad occur in neither the full source, supplied preview, nor PNG. The reconstructed prompt JSON hash is `97fc1bb5f5377d16c895aca03e01cc61bd61755639439a195b335f4f59f25769`; this is deterministic audit reconstruction, not a captured external wire request.

The lead's final explanation refers to a 12-row preview; 12 is the lead/designer preview limit, not the reviewer's 30. The reviewer rulebook already says not to judge completeness/facts outside supplied rows and to omit uncertain findings. The observed failure is treating absence from partial evidence as fabrication, plus naming two nonexistent visible countries. It does not, by itself, isolate blame to the model versus prompt/context design.

### Actual defect versus false finding

Case 25 is the useful positive-control failure: `dual_axes` rendering reports `drawn_rows=9`, `dropped_rows=1`, and the first image starts at 2017. The null growth value should not erase the independently valid 2016 count. The final table contains all ten source rows, including `2016, 211, null`. This is an executable renderer/binding limitation with a successful lead-directed fallback. The stored compromise already exposes the dropped row before image review.

Case 26 shows the opposite behavior. All five long X labels are fully inside the first PNG. A small left Y-title/legend-marker contact is visible, but neither reviewer finding identifies it. The lead accepts the claimed X-label clipping and changes only width/height to 3200×1800, producing a 9600×5400 PNG. Its labels remain complete; fit-to-width text becomes tiny, so this is not a demonstrated usability improvement. This audit viewed the retained PNG at both available display sizes, not a live web viewport.

The five `design_visualization` calls in 26 are: initial design; repair call rejected for missing direction; one accepted resize; another call rejected for missing direction; proposed table fallback rejected because the one-visual-repair limit is exhausted. There are only two actual designer calls and two PNGs, not an infinite render loop. The first designer takes 28.53s and the second 14.64s; the two visual reviews take 1.03s and 1.55s. The total is 79.18s / 18 requests. This proves both unnecessary workflow overhead and significant specialist latency, not that the reviewer itself consumed most wall time. Case 24 also takes 40.12s with a single render and no repair, so latency cannot be attributed exclusively to loops.

Case 27 separates good lead judgment from reviewer error: the designer initially translates source literals despite a keep-original direction; lead removes those mappings before rendering. Then the reviewer demands them again, incorrectly treating Arabic `columnLabels` as instructions to translate category values. The lead declines this false repair. This is not evidence for disabling all review: case 25 required it, while 27 demonstrates that the lead can reject an incorrect finding.

### Scope and final-delivery gaps

Case 30's unapproved code decoding is an upstream lead/designer fidelity error. The scoped visual inspector is not required to rediscover the codebook or overrule a spec that visibly renders as written. The missing check is comparison with authoritative handoff intent, not broader visual review.

Case 29 explains the technical limit correctly, but its final text requires the owner to split the file or supply a summary after the brief explicitly says not to request new data. No `ask_user` call occurs. A tool-name-only question detector therefore cannot establish compliance with the no-new-data rule.

For 31, an exact comparison of the safe `app_name` column confirms all 1,000 source values survive in saved artifact order, including duplicates. Geometry was excluded and never printed during audit. The final claim of a complete scrollable card is not supported by returned evidence: publication returns 50 artifact preview rows, while its Markdown card has 20 rows and the explicit footer “20 من 1000 صفًا”. `vis_agent/card.py:10` sets `CARD_ROWS=20`; `_table` slices at that limit. `LeadArtifact.from_artifact` limits the tool preview to `LEAD_ROWS=50`. The `/artifacts/{artifact_id}` endpoint can return full persisted data, but no full-table or artifact link appears in the final response. This is not a finding that ordinary scrollbar cropping is bad; no functional scrolling table was supplied in these saved outputs, and no UI was tested.

### Validation and limits

- All 17 source files still hash to each checkpoint's `source_csv_sha256`; all 17 retained PNGs exactly match sidecar hashes and render IDs.
- Shared model/settings/provider/concurrency and application/evaluator/lead/optimization/runtime-contract fingerprints are identical across assigned checkpoints. Only `effective_contract_sha256` varies, as expected per case.
- Audits are development-case agent judgments. They do not replace human-labelled reviewer gold or prove production/higher-cardinality generalization.
- A faithful saved table, a faithful PNG, and a delivered final response are distinct observations. No raw result, runtime, evaluator, source CSV, or case-bank file was edited for this audit.
