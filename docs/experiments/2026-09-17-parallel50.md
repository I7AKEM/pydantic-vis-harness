## Scroll qualification

The user's distinction is important: a working scrollable table may legitimately
show a cropped viewport. That is not data corruption or automatically a visual
defect. Audits distinguish that behavior from unreadable/clipped glyphs and from
a static PNG that claims to show a complete table. We separately check complete
accessible source/HTML content. In the current first-segment17row case, both
models' PNGs actually show all17 rows with correct headers: Gemma rejects them
for a nonexistent header swap, not for genuine viewport clipping.

The GLM defects are clipped donut labels and population-bar labels colliding

Confirmed first-segment issues, from actual images and raw tool messages:

1. **Owner-specific repair gate blocks supported corrections.** A real clipped
   GLM donut can be fixed with supported `labels off`, but an `owner=renderer`
   finding blocks the designer tool. Repeated attempted repairs, publication,
   then `revise` can exhaust the shared request cap without a final response.
2. **False visual review initiates unnecessary repair.** The first Claude donut
   already has correct readable labels and legend; Gemma alleges a nonexistent
   mapping swap. Correct17row tables are similarly rejected in both arms.
3. **Contradictory structured errors are not retracted.** Findings marked error
   state that all values are correct in their own text. The structural verdict
   stays `revise`; a confident final prose assertion does not fix that state.
4. **Lead/provider latency is independent of designer latency.** One Claude-arm
   case times out in the GLM lead before design. Another has a correct published
   chart after roughly22s, then spends92.81s waiting for the GLM final response.
   These cannot be attributed to Claude's chart design time.
5. **A numeric-only answer checker misses semantic invention.** A GLM regional
   gender response decodes F/M despite an explicit no-codebook instruction.
   Its image retains the correct codes. Conversely, digits in a literal column
   name produce a false numeric rejection in another case.
6. **An explicit label toggle destroys useful library defaults.** In the GLM
   donut, `labels on` replaces the package labels array, removing outside
   placement and overlap hiding. A same-data/same-size local replay omitting
   only that option restores complete, readable outside labels. All other
   input/configuration fields remain identical. Claude's good first donut
   omitted the option. This is a harness API-abstraction issue, not evidence
   that GPT-Vis cannot render outside labels. Evidence and replay are in
   `evals/lead/labels-on-probe/README.md`.

These are provisional findings from retained cases, not an explanation inferred
from aggregate scores. Runtime/evaluator fixes are deferred until the frozen
comparison is finished. Any later scoring correction must be a separate audited
rescore with raw results unchanged.
